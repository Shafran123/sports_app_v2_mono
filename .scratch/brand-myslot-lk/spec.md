# Rebrand: Spots → MySlot.LK

Status: ready-for-agent

## Problem Statement

The platform currently brands itself "Spots" — the config default, the hardcoded wordmarks, page titles, transactional emails, SMS, and the internal package namespace all say Spots. The owner wants the brand to be **MySlot.LK** permanently. The brand is supposed to be admin-configurable (see CONTEXT.md) but the mechanism is incomplete: `brand_name` is readable but not settable through the admin API, and most visible surfaces hardcode "Spots" in JSX instead of reading the config. The rename must make MySlot.LK the brand everywhere a user, venue owner, or admin sees it, make the config mechanism actually work end to end, and leave historical records (ADRs, past specs, past tickets, git history) untouched.

## Solution

### Brand identity

- The brand name is **MySlot.LK** (capital M, capital S, capital L, capital K, dot-separated).
- Wordmark lockup: **"MySlot"** in dark ink with the **`.`** and **`.LK`** rendered in the brand green — mirrors the existing `Spots<span>.</span>` treatment.
- Taglines stay as-is, brand word replaced: "MySlot.LK — Find Your Game", "MySlot.LK — book courts, join games, find players.", "Welcome to MySlot.LK!".
- SMS prefixes become `MySlot.LK: …`.

### Config-driven brand (the mechanism made real)
- `brand_name` stays the config key (it is generic data, not a code identifier).
- Server: `setConfig` must accept `brand_name` (string, trimmed, non-empty, length-capped) alongside the existing flags and `tax_rate`, with the same audit trail.
- Admin Settings page gains a Brand field (with the flags/tax pattern: live read, save, audit).
- Every user-visible JSX surface reads `brand_name` from public config with a **MySlot.LK** fallback: player nav wordmark, footer, login form, register form, "join Spots" home copy, admin sidebar wordmarks, admin login, events copy already config-driven.
- Next.js page metadata (`<title>`) is read server-side from the public config (async metadata in the layout) with fallback "MySlot.LK — Find Your Game" / "MySlot.LK Console".
- Non-interactive, code-baked surfaces that cannot be config-driven get the new default baked in: email FROM, email shell footer, welcome email, booking/reminder/bill email copy, SMS templates, daily digest subject, phone-verification SMS.

### Email identity
- Default FROM becomes `MySlot.LK <no-reply@myslot.lk>` (still env-overridable via `FROM_EMAIL`).
- Demo seed users move to `admin@myslot.lk`, `owner@myslot.lk`, `player@myslot.lk`.
- Operational note (not a code task): myslot.lk must be verified as a sending domain on Mailgun for delivery; until then the env override keeps mail flowing.

### Database
- New migration `0015_brand_myslot_lk.sql` upserts `brand_name = "MySlot.LK"` and updates the three demo users' emails — existing seeded DBs update without a reset.
- `0002_seed.sql` edited so fresh installs seed the new brand and emails directly.

### Internal identifiers
- Packages `@spots/api`, `@spots/auth`, `@spots/config`, `@spots/types`, `@spots/ui`, `@spots/utils` → `@myslot/*` (package.json names, tsconfig `display`, all imports across `apps/*` and `packages/*`).
- Root `package.json` name `spots` → `myslot`, `dev:user` / `dev:admin` script filters updated.
- `pnpm-lock.yaml` regenerated by re-running install.
- Sweep `dev.sh`, `turbo.json` for package references.
- The Firebase service-key JSON filename (`sports-app-20029-…`) is gitignored with no code references — rename is optional, not required.
- Out of scope (external): the Firebase project name in the Google console, the GitHub repo name `sports_app_v2_mono`, the local folder name, PayHere merchant name.

### Tests
- Existing fixtures asserting `brand_name: "Spots"` or hardcoded "Spots" wordmarks are updated to the new brand/fallback.
- New/updated tests: brand field settable via admin config API (reject blank / overlong), public config returns the new default, email/SMS templates contain the new brand, config-driven nav/footer use the configured brand.

### Docs (living only)
- `CONTEXT.md` intro: default brand is now MySlot.LK; add a **Brand Name** glossary term.
- `sp_be/README.md` first line updated.
- ADRs, old specs, and old ticket files are history — untouched.

## Implementation Decisions

- Branding is delivered in one cutover, not staged: no transitional "Spots → MySlot.LK" period.
- The wordmark treatment lives in the shared UI where a shared lockup exists; surfaces that hand-roll the lockup apply the `MySlot` + green `.LK` pattern consistently.
- The FE already has a `brand_name` field in the public config envelope — no API shape change for reading; only the admin-write path needs the new allowed key.
- The rename order is backend first (migration + copy), then internal package rename, then user/admin app config-driven surfaces — so no ticket edits a file another is mid-rewrite on.

## Out of Scope

Changing the brand by a future admin remains a config change, but the non-interactive surfaces (emails, SMS, digest) are code-baked and are NOT re-read from config — a future rename needs a code touch there. Slogan/tagline rewrite. App icon redesign (the SVG has no text). Native/iOS/Android branding (no native apps). Production launch.

## Further Notes

- The `brand_name` key deliberately stays named `brand_name` even though the brand is now MySlot.LK — it's a generic config key, and renaming it would be a data migration for no user value.
- The admin Settings page needs the brand field for the "admin-configurable" promise to be true; today `setConfig` rejects `brand_name` as unknown (sp_be/utils/featureFlags.js).
