# 0048 — Playwright e2e strategy

UI testing (user + owner flows, admin P2) runs as a separate Playwright suite in `e2e/` against the real local stack — Express backend, Postgres, and the Next apps — on a **fresh throwaway database per run** (`sports_e2e`, dropped and recreated, then migrated + seeded + fixture SQL), booted by Playwright's `webServer`. Platform roles (owner, admin) authenticate by **injecting HS256 JWTs** (signed with `JWT_SECRET`, accepted because the backend runs with `NODE_ENV=test`) into the app's `localStorage`; Site Customer sessions are seeded as real DB rows (they are opaque bearer tokens, not mintable). Because the console apps restore sessions through Firebase's `onAuthStateChanged` (which the harness cannot reach), a **minimal env-gated seam** (`NEXT_PUBLIC_E2E=1`, packages/auth `AuthProvider`) restores the platform session from the persisted token — never set outside the harness. The one real-form login covered is Site Customer registration/sign-in. Payments are **cash-only** — PayHere stays with an external tester, and reCAPTCHA/email/SMS are disabled (unconfigured secrets) so nothing external is ever hit; a local stub answers the Supabase storage bucket check. e2e is deliberately kept **out of `pnpm test`** (turbo) and out of CI for now — `pnpm e2e` / `pnpm e2e:ui` only.

**Considered options:** driving the real Firebase UI login per spec (slow, flaky, not locally reproducible), mocking the backend (loses the integration value), and adding a frontend auth seam (`__E2E__` flag). Token injection was chosen because it exercises the real backend auth contract end-to-end while staying deterministic; a frontend seam remains the fallback if token injection proves insufficient.
